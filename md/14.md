# 📘 Lecture 14 – Feed API & Pagination

- Feed ke andar kaunse users **dikhne chahiye** aur kaunse nahi  
- Pagination ka concept aur uski need samajhte hain  
- MongoDB query operators ka use samajhte hain  

---

## What is Feed?

Feed ka matlab:
- User ko **naye log dikhana**  
- Jinse user ne **abhi tak interaction nahi kiya ho**


Example:
- Tinder feed
- Instagram suggestions
- LinkedIn “People you may know”

Feed ka goal:
> **Discover new users**

---

## Feed API – Core Idea

Feed API:
- Database se users fetch karti hai  
- Lekin **filtered form mein**

Har user ko:
- Sirf relevant profiles dikhni chahiye  
- Repeat ya unwanted profiles nahi dikhni chahiye  

---

## Feed Mein Kaunse Users Nahi Dikhne Chahiye

Feed API mein following users **exclude** hone chahiye:

1. **Khud ka profile**
   - User ko apna hi card nahi dikhna chahiye  

2. **Jinko already request bhej di**
   - Dubara wahi user dikhna pointless hai  

3. **Jinko ignore kiya**
   - Ignore ka matlab = not interested  

4. **Jinhone hume request bheji thi aur humne reject ki**
   - Dono taraf se interest nahi raha  

5. **Accepted connections**
   - Jo already connection ban chuke hain  

Feed ka matlab:
> “Completely new & unexplored users”

---

## Feed API – Thought Process

Feed banane se pehle socho:
1. Logged-in user kaun hai?
2. Usne kisko request bheji hai?
3. Kisne usko request bheji hai?
4. Kaunse requests accepted / rejected / ignored hain?
5. In sab users ko feed se hata do

Jo bache:
- Wahi feed ke candidates hain

---

## Why Feed Logic is Complex

Feed simple list nahi hota:
- Ye **business logic heavy** hota hai  
- Multiple conditions combine hoti hain  

Isliye:
- Proper query design important hota hai  
- Galat logic se duplicate ya unwanted profiles dikh sakti hain  

---

## MongoDB Query Operators

Feed banate time hum **query operators** use karte hain.

---

## `$in` Operator

`$in` ka matlab:
- “Value in this list ho”

Use case:
- Agar hume kuch userIds ka list mile
- Aur unko exclude / include karna ho

Helpful jab:
- Multiple IDs ke against filter lagana ho  

---

## `$and` Operator

`$and` ka matlab:
- Saari conditions true honi chahiye

Use case:
- Jab multiple strict conditions apply karni ho  

Example scenario:
- User active bhi ho  
- Aur connection request bhi na ho  

---

## `$or` Operator

`$or` ka matlab:
- Koi bhi ek condition true ho jaye

Use case:
- Jab alternative cases handle karne ho  

Example scenario:
- fromUserId bhi ho sakta hai  
- ya toUserId bhi  

---

## Why Query Operators are Important

Query operators:
- Complex logic ko simple banate hain  
- Database-level filtering dete hain  
- Performance improve karte hain  

Bina operators ke:
- Zyada data memory mein aayega  
- App slow ho jayega  

---

## What is Pagination?

Pagination ka matlab:
- Data ko **small chunks** mein dikhana  

Example:
- Ek page pe 10 users
- Next page pe agle 10 users

---

## Why Pagination is Needed

Without pagination:
- Ek hi request mein bahut zyada data aayega  
- Response slow hoga  
- UI lag karegi  

Pagination:
- Performance improve karti hai  
- Better user experience deti hai  

---

## Pagination in Feed API

Feed API mein:
- Ek baar mein limited users dikhte hain  
- User scroll / next page kare → naye users load hote hain  

Isse:
- Infinite scroll jaisa experience milta hai  

---

## Skip vs Limit

### `limit`
- Ek request mein **kitne documents** chahiye  
- Example: 10 users per page  

### `skip`
- Kitne documents **chhodne hain**  
- Example: page 2 → pehle 10 skip  

---

## Difference Between Skip & Limit

| Concept | Purpose |
|------|--------|
| limit | Data ka size control karta hai |
| skip | Offset control karta hai |

Dono milkar:
- Pagination implement karte hain  

---

## Pagination – Real World Benefit

- Fast APIs  
- Low server load  
- Smooth scrolling  
- Scalable system
