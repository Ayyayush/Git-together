# Lecture 10 – Authentication using JWT & Cookies

## Overview
Is lecture mein hum:
- Authentication aur Authorization ka difference samajhte hain  
- JWT (JSON Web Token) use karke login system banate hain  
- Cookies ka role samajhte hain  
- Auth middleware ke through secure APIs banana seekhte hain  

---

## Authentication vs Authorization

### Authentication  
Ye check karta hai:
> “Tum kaun ho?”

Login process authentication hota hai.

### Authorization  
Ye check karta hai:
> “Tum kya kar sakte ho?”

Example:
- Normal user apna profile dekh sakta hai  
- Admin sabka data dekh sakta hai  

---

## JWT (JSON Web Token)

JWT ek **industry-standard digital token** hai jo:
- User ko uniquely identify karta hai  
- Login ke baad generate hota hai  
- Har request ke saath verify hota hai  

JWT user ki **temporary digital identity** hota hai.

---

## High-Level Flow

1. User login karta hai  
2. Server user ko verify karta hai  
3. Server JWT token generate karta hai  
4. JWT cookie ke andar store hota hai  
5. Browser har request ke saath cookie bhejta hai  
6. Server JWT verify karta hai  
7. Agar token valid → request allowed  
8. Agar invalid/expired → request rejected  

---

## Why JWT is Stored in Cookies

Agar har API ke saath manually token bhejna pade:
- Frontend complicated ho jata hai  
- Security risk badhta hai  

Cookies ka fayda:
- Browser automatically token bhej deta hai  
- Frontend ko token manage nahi karna padta  

Isliye:
> JWT ko cookie ke andar store kiya jata hai  

---

## Cookie Concept

Cookie ek small data hota hai jo:
- Browser mein store hota hai  
- Har request ke saath server ko automatically jata hai  

JWT cookie ke andar hota hai — jaise **digital entry pass**.

---

## Cookie Expiry

Cookie ke saath expiry hoti hai.  
Jab expire hota hai:
- User automatically logout ho jata hai  
- Protected APIs fail ho jaati hain  

Isse session secure rehta hai.

---

## cookie-parser Middleware

Express by default cookies read nahi karta.  
`cookie-parser` middleware:
- Cookie ko parse karta hai  
- `req.cookies` mein JWT available karata hai  

Iske bina JWT verify nahi ho sakta.

---

## JWT Token Structure

JWT 3 parts mein hota hai:

Header.Payload.Signature

- Header → algorithm info  
- Payload → userId + metadata  
- Signature → secret key se bana security proof  

Agar koi data change kare → signature invalid ho jata hai.

---

## Why JWT is Secure

JWT:
- Signed hota hai  
- Tampering detect hoti hai  
- Server bina database call ke token verify kar sakta hai  

Isse performance aur security dono milti hai.

---

## Token Hijacking

Agar cookie chori ho jaye:
- Attacker user ban sakta hai  

Isliye:
- Cookies ko `httpOnly`, `secure`, `expiry` ke saath set kiya jata hai  
- JWT secret strong hota hai  

---

## Auth Middleware

Auth middleware ka kaam:
- Request se JWT nikalna  
- Token verify karna  
- UserId extract karna  
- Unauthorized users ko block karna  

Iska fayda:
- Har API mein token verify code repeat nahi hota  
- Centralized security milti hai  

---

## JWT Expiry

JWT ke saath:
- Expiry time set hota hai  
- Expire hone par token invalid ho jata hai  
- User ko dobara login karna padta hai  

Ye auto-logout ka kaam karta hai.

---

## Connection Request API (Auth Protected)

Connection request jaise actions:
- Sirf logged-in user hi kar sakta hai  
- Auth middleware se protect kiya jata hai  
- JWT se user identity milti hai  

---

## Refactoring using Mongoose Methods

User schema mein methods banaye jaate hain:
- JWT generate karne ke liye  
- Password verify karne ke liye  

Isse:
- Auth logic models ke andar shift ho jata hai  
- Controller code clean ho jata hai  

---

## Key Takeaways

- Authentication login hota hai  
- Authorization access control hota hai  
- JWT user ki digital identity hai  
- Cookies JWT ko automatically send karti hain  
- Token expiry auto logout karti hai  
- Auth middleware security enforce karta hai  
- JWT tamper-proof hota hai
