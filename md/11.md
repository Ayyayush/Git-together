# 📘 Lecture 11 – Diving into APIs & Express Router

---

## 🧠 Why We Need API Separation?

Hum **ek hi file (`app.js`) me saari APIs** nahi bana sakte, kyunki:

- Code messy ho jata hai  
- Maintain karna mushkil hota hai  
- Scaling ke time problems aati hain  

👉 **Solution:** APIs ko logically group karna aur **Express Router** use karna.

---

## 🔍 App-Centric Thinking (Real World Approach)

Hum **user ke point of view** se APIs design karte hain.

👉 Example:  
**Tinder app open karo aur socho:**
- Signup / Login
- Profile dekhna
- Like / Pass karna
- Requests accept / reject

Isi thinking se APIs design hoti hain.

---

## 🧩 Logical API Grouping (Best Practice)

APIs ko **feature ke basis par** group karna chahiye:

- Authentication
- Profile
- Requests
- Connections
- Feed

> ❗ Grouping kisi bhi format me ho sakti hai,  
> but **logical separation best hoti hai**.

---

## 🔑 Common APIs in Our App

- **POST** – Signup API  
- **POST** – Login API  
- **POST** – Logout API  
- **GET** – Profile API  
- **PATCH** – Update Profile API  
- **DELETE** – Delete Profile API  
- **POST** – Send Connection Request  
- **GET** – Received Requests  
- **PATCH** – Update Password API  

---

## 💖 Tinder Logic (Like / Pass)

- **Like** → `interested`
- **Pass** → `ignored`

> Profile **like = interested**  
> Profile **reject = ignored**

## 📊 Request Status Values

These values define the lifecycle of a request:

- `ignored`
- `interested`
- `accepted`
- `rejected`

---

## 🔄 Status Lifecycle
interested → accepted → connection created
interested → rejected → request closed
ignored → no further action

## 🧱 Express Router – Why & How?

### ❓ Problem
Agar saari APIs `app.js` me likhenge:
- File bahut badi ho jayegi
- Readability kam ho jayegi

---

### ✅ Solution – Express Router

Hum **multiple routers** banate hain:

- `authRouter`
- `profileRouter`
- `requestRouter`

Each router handles **similar routes only**.

---

## 🔁 app.use vs router.use

``` js
app.use("/auth", authRouter);
app.use()
→ Application level routing

🔹 router.use()
→ Feature specific routing

app.use() works like a route gateway ```
