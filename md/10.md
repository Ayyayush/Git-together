# Lecture 10 – Authentication using JWT & Cookies

## Overview
Is lecture mein hum:
- Authentication aur Authorization ka difference samajhte hain
- JWT (JSON Web Token) use karke login system banate hain
- Cookies ka role samajhte hain
- Secure user sessions kaise maintain hote hain, ye seekhte hain

---

## Authentication vs Authorization

### Authentication  
Ye check karta hai:
> “Tum kaun ho?”

Login process authentication hota hai.

### Authorization  
Ye check karta hai:
> “Tum kya kya kar sakte ho?”

Example:
- Normal user profile dekh sakta hai
- Admin sabka data dekh sakta hai

---

## JWT (JSON Web Token)

JWT ek **industry-standard token** hai jo:
- User ko uniquely identify karta hai
- Login ke baad generate hota hai
- Har request ke saath verify hota hai

JWT ek **temporary digital identity** hota hai user ke liye.

---

## High-Level Flow

1. User login karta hai  
2. Server user ko verify karta hai  
3. Server JWT token generate karta hai  
4. JWT cookie ke andar store hota hai  
5. Browser har request ke saath JWT bhejta hai  
6. Server JWT verify karta hai  
7. Agar token valid → request allowed  
8. Agar invalid/expired → request rejected  

---

## Why We Use Cookies with JWT

Agar har API ke saath manually token bhejna pade:
- Frontend complicated ho jata hai

Cookies ka use:
- Browser automatically cookie har request ke saath bhej deta hai
- User ko token handle nahi karna padta

Isliye:
> JWT ko cookie ke andar store kiya jata hai

---

## Cookie Concept

Cookie ek small data hota hai jo:
- Browser mein store hota hai
- Har request ke saath server ko send hota hai

JWT cookie ke andar hota hai, jaise:
- User ka digital pass

---

## Cookie Expiry

Cookie ke saath:
- Expiry date set hoti hai
- Jab expire hota hai → user automatically logout ho jata hai

Agar request ke beech cookie expire ho jaaye:
- Server request reject kar deta hai

---

## cookie-parser Middleware

Express cookie ko direct nahi padhta.  
Cookie read karne ke liye:
- `cookie-parser` middleware use hota hai

Ye middleware:
- Cookie ko parse karta hai
- `req.cookies` ke andar available kara deta hai

---

## JWT Token Structure

JWT 3 parts mein hota hai:

1. Header  
2. Payload  
3. Signature  

Format:


- Header → algorithm info  
- Payload → user data  
- Signature → security proof  

---

## Why JWT is Secure

JWT:
- Signed hota hai (secret key se)
- Agar data change kiya gaya → signature invalid ho jata hai
- Server bina database hit kiye token verify kar sakta hai

---

## Token Hijacking

Agar kisi ne cookie chura li:
- Wo user ban sakta hai

Isliye:
- Cookies secure, httpOnly aur expiry ke saath set ki jaati hain
- JWT secret strong hona chahiye

---

## JWT Package

We use:
- `jsonwebtoken`

Is library se:
- Token sign hota hai
- Token verify hota hai

---

## Why JWT + Cookies is Industry Standard

- Stateless authentication
- Fast verification
- Scalable
- Frontend ke liye easy
- Backend ke liye secure
