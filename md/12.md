# 📘 Lecture 12 – Connection Requests, Schemas & Indexing

## 🔹 Recap
- Ab tak hum **sirf User Schema** ke saath kaam kar rahe the  
- Ab application thodi **complex** hone wali hai  
- Isliye hume **Connection Request** ke liye bhi **separate schema** banana padega  

---

## 🤝 Why Connection Request Needs Its Own Schema?
- Connection request **do users ke beech ka relation** hota hai  
- Ye ek **independent entity** hai  
- Isko User schema ke andar rakhna ❌ **messy & unmaintainable** ho jayega  

👉 Best practice:  
> **Keep ConnectionRequest schema separate from User schema**

---

## 🧩 Connection Request Schema – Key Points
- Connection request **exist hi nahi kar sakta** bina:
  - `fromUserId`
  - `toUserId`
  - `status`
- Ye fields **mandatory** honi chahiye  
- Schema me:
  - `timestamps` use karte hain  
  - APIs ke around **try–catch blocks** mandatory hote hain  

---

## 🔒 Enum – Restricting Values
- Jab hume kisi field ke liye **limited values allow** karni ho  
- Tab hum **enum** use karte hain  

Example:  
`status` sirf in values me se ek ho sakta hai:
- `pending`
- `interested`
- `ignored`
- `accepted`
- `rejected`

👉 Enum ka fayda:
- Invalid values database mein nahi jaati  
- Data **consistent & predictable** rehta hai  

---

## ⏱ Timestamps
- MongoDB automatically maintain karta hai:
  - `createdAt`
  - `updatedAt`

Isse hum track kar sakte hain:
- Request kab bheji gayi  
- Kab accept / reject hui  

---

## 🚨 Errors & Middleware
- Pre / Post middleware me error handling bahut important hai  
- Common mistakes:
  - `next()` call bhool jana  
  - Async error handle na karna  

Best practice:
- Hamesha `try–catch` lagao  
- Clear aur meaningful error messages bhejo  

---

# 📌 What is Indexing in Database?

Indexing ka matlab:
- Database ko **fast banana**

Jaise book ke end me index hota hai,  
waise hi database me index hota hai.

---

## ❌ Problem Without Indexing
- Jaise-jaise database grow karta hai:
  - Queries **slow** ho jaati hain  
- Example:
  - Database me **Virat** naam ke 1000 users hain  
  - `firstName = "Virat"` search karoge  
  - DB ko poori collection scan karni padegi ❌  

Ye cheez:
- APIs ko expensive banati hai  
- Database ko hang bhi kar sakti hai  

---

## ⚡ Solution: Indexing
- Index database ko batata hai:
  > “Is field pe search zyada hoti hai”

Indexing se:
- Queries fast hoti hain  
- Performance improve hoti hai  
- Large databases manageable rehte hain  

---

## 📧 Indexing on Email
- Agar kisi field pe:
  - `unique: true` lagaya ho  

Toh:
- MongoDB automatically us field pe **index bana deta hai**

Example:
- Email field normally:
  - Unique hoti hai  
  - Automatically indexed hoti hai  

---

## 🔍 Indexing on Other Fields
Agar frequently:
- `firstName` ke basis pe search hoti hai  
- Ya sorting hoti hai  

Toh:
- `firstName` pe index lagana performance improve karta hai  

Indexing:
- Search + sorting dono ko fast banati hai  

---

## 📚 Types of Indexes

### 🔹 Normal Index
- Single field pe index
- Fast searching ke liye use hota hai

---

### 🔹 Unique Index
- Duplicate values allow nahi karta  
- Mostly:
  - Email
  - Username  
ke liye use hota hai  

---

### 🔹 Sparse Index
- Sirf un documents ko index karta hai jisme field present hoti hai  
- Useful jab:
  - Field optional ho  
  - Sab documents me present na ho  

---

## 🔗 Compound Indexing

Compound index ka matlab:
- **Multiple fields** par ek saath index

Example:
- `fromUserId + toUserId`

Connection Request ke case me:
- Same user pair ke beech duplicate request nahi honi chahiye  

Compound indexing:
- Duplicate requests prevent karti hai  
- Queries ko extremely fast banati hai  

---

## ⚠️ Cost of Indexing
- Har index ka:
  - Storage cost hota hai  
  - Write performance pe thoda impact hota hai  

Isliye:
> **Unnecessary indexing avoid karo**

Sirf wahi fields index karo:
- Jinpe frequently search / filter / sort hota ho  

---

## 🧠 Key Takeaways
- Connection Request ke liye separate schema best practice hai  
- Enum se field values restrict hoti hain  
- Indexing performance ke liye critical hai  
- Unique fields automatically indexed hote hain  
- Compound indexing duplicate relations prevent karti hai  
- Large databases ke liye indexing mandatory hoti hai  
- Clean schema separation code ko scalable banata hai  

---

Lecture 12 mein hum connection requests ke liye proper schema design, enum-based status control, aur database indexing ka use karke scalable aur high-performance backend banana seekhte hain.
